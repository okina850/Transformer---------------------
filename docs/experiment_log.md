## 2026-08-16 | Phase 0 | Day 1: 誤差指標・線形化最小二乗・分母4設計の実装と初回測定

### やったこと

- `src/rational/metrics.py`: 誤差指標（sup / L2 / RMS / 重み付き）、
  グリッド（等間隔・Chebyshev）、重み関数、平滑性指標
- `src/rational/denominators.py`: 分母4設計（`free` / `abs` / `sqrt` / `square`）
- `src/rational/fitting.py`: 線形化最小二乗、Sanathanan–Koerner 反復、非線形最小二乗

設計上の判断:
- **フィット用グリッドと誤差評価用グリッドを分離**した（評価側は10倍密、半格子ずらし）。
  同じ点で当てはめて同じ点で測ると点の間の誤差を見逃すため。
- **L2 の数値積分に Simpson 則を使用。** 被積分関数が `1+|A(x)|` 型の分母により
  微分不連続点を持ちうるので、滑らかさを仮定する Gauss-Legendre は不適。
- **Sanathanan–Koerner 反復を実装。** 線形化最小二乗は `||P - fQ||` を最小化するが、
  本当に最小化したいのは `||P/Q - f||` であり、前者は暗黙に `Q(x)` で重み付けした
  誤差を測っている。SK 反復は前回の `Q` で各行を割ることでこのバイアスを消す古典的手法。

### 測定結果1: Padé@0 は広区間では使い物にならない

目標 `gelu_tanh`、型 [5,4]、sup ノルム誤差:

| 手法 | [-3, 3] | [-6, 6] |
|---|---|---|
| Padé@0（論文の公式初期化の作り方） | 9.46e-02 | **1.03e+00** |
| 線形化最小二乗 | 6.87e-04 | 8.38e-03 |
| 線形化 + SK 反復(5回) | 9.10e-04 | **3.52e-03** |
| 非線形最小二乗 | 8.39e-04 | 3.67e-03 |

- [-6,6] で Padé@0 は区間フィットより **sup 誤差が約 280 倍悪い**。
  sup 誤差 1.03 は GELU の値そのものと同オーダーであり、近似として破綻している。
- SK 反復は [-6,6] でコストを 8.17e-3 → 4.17e-3 と約2倍改善。広区間ほど効く。
  （[-3,3] では効果が小さい。Q の変動が小さいのでバイアスも小さいため。）
- 非線形最小二乗は SK 反復とほぼ同じ解に到達。SK が十分良い初期値であることの確認になる。

### 測定結果2: 初期値によっては局所解に落ちる（多点スタートは必須）

`free` 分母、[5,4]、[-6,6] での非線形最小二乗のコスト:

| 初期値 | cost |
|---|---|
| 線形化解 | 4.158145e-03 |
| Padé@0 | 4.158145e-03 |
| ランダム摂動 | **3.705520e+00**（約900倍悪い） |

出自の異なる2つの初期値（線形化解・Padé@0）が **1e-9 の精度で同一解に収束**した。
これを大域解の根拠とする（CLAUDE.md の「seed 3つ」の趣旨をこの形で満たす）。
一方ランダム初期値は完全に失敗しており、**「線形化で解いてから非線形で仕上げる」
2段構えは省略できない**ことが確認された。

### 測定結果3【重要】: 分母設計の裾の挙動（論点A の定量化）

型 [5,4] での実効分母次数と裾:

| 設計 | Q(x) | 実効分母次数 | 裾 F ~ x^p | 平滑性 |
|---|---|---|---|---|
| `abs` (PAU) | 1+\|A\| | 4 | **x^1** | 折れうる |
| `sqrt` | 1+√(ε+A²) | 4 | **x^1** | C^∞ |
| `square` | 1+A² | **8** | **x^-3** | C^∞ |

→ **`sqrt` は PAU と実効次数も裾も一致し、違いが平滑性だけになる。**
一方 `square` は裾も同時に変わる（線形増加 → 0 への減衰）。
統制された比較としては `sqrt` の方が筋が良い（下の「判断待ち」参照）。

### 測定結果4【最重要】: PAU の絶対値は、GELU/SiLU 近似では**一度も発動しない**

`abs` 分母でフィットした結果、`A(x)` の **符号変化が全条件でゼロ**だった。

| 目標 | 型 | A(x) の符号変化 | A(x) の値域 on [-6,6] |
|---|---|---|---|
| gelu_tanh | [3,2] | なし | [0, +2.10] |
| gelu_tanh | [4,3] | なし | [0, +7.29] |
| gelu_tanh | [5,4] | なし | [0, +10.8] |
| gelu_tanh | [6,5] | なし | [0, +4.18] |
| gelu_tanh | [7,6] | なし | [-120, 0] |
| silu | [3,2]〜[7,6] | すべてなし | すべて片側 |

**解釈**: `A(x)` は定数項を持たないので `A(0)=0` が常に成立し、x=0 は必ず根になる。
しかし GELU/SiLU の最適な分母は**ほぼ偶関数**（`b_1 ≈ b_3 ≈ 0`）になるため、
`A(x) ≈ b_2x² + b_4x⁴ + …` となり原点で**接するだけで横切らない**。
このとき `|A| = ±A` であり、**絶対値は恒等写像として振る舞い、Q は完全に平滑**。

→ **Boullé et al. の「PAU は非平滑」という批判は、GELU/SiLU の近似という文脈では
初期化時点では当たらない。** 本研究の RQ2 をこのまま
「平滑分母は PAU より良いか」と立てると、比較の前提が崩れている。

**ただしこれは RQ2 を捨てる理由ではなく、鋭くする理由である**（下の「判断待ち」参照）:
折れ点が生じるのは学習中に `b_1` が 0 から離れて `A` が原点を横切るようになったとき。
そしてそのとき折れ点は **x=0 ちょうど**、つまり pre-activation 分布の最頻値に一致する。
「最も頻繁に通る点に微分不連続が立つ」ことになるので、実害があるとすればここ。

### 実装メモ

- 折れ点の判定は **`A(x)=0` の根ではなく符号変化**で行う実装に修正した。
  根で判定すると x=0 の重根（接するだけ）を折れ点と誤検出する。
  `AbsDenominator.kinks()` は密グリッド上の符号変化を返し、
  `roots_of_A()` は参考用に根を返す。

### 判断待ち → **両方とも承認された**（下の「方針変更」エントリを参照）

1. RQ2 の再定式化 → 承認。新 RQ3 として research_context §4 に反映済み
2. Phase 1 の R3/R4 の分母を `square` から `sqrt` に変更 → 承認。
   `square` は Phase 0 の近似誤差比較には残す

## 2026-08-16 | 方針変更 | RAFT・KAT の発見により研究の位置づけを再構成

### 何が起きたか

ユーザーが先行研究2本を追加し、`docs/research_context.md` を改訂2に更新した。

- **RAFT** (Fang, Lee, Moosavi, Gurevych, EACL 2023, arXiv:2208.14111v3)
  `docs/refs/Transformers_with_Learnable_Activation_Functions.pdf`
- **KAT** (Yang & Wang, NUS) `docs/refs/Kolmogorov_ArnoldTransformer.pdf`

**当初の新規性の主張「Transformer 言語モデルへの初適用」は成立しない。**
RAFT が safe PAU をそのまま採用し、encoder-only Transformer (BERT系, 12層, hidden 768)
を English Wikipedia + MLM でスクラッチ事前学習し、GELU ベースライン (FAFT) を上回る
結果を報告している（validation PPL: RAFT 5.00 vs FAFT 5.18）。層ごとの学習後形状の
可視化・分析も済んでいる。

### 新しい位置づけ（research_context 改訂2）

- **主軸**: decoder-only 設定での**追試（replication study）**
- **副軸**: 分母設計の検討（先行研究がいずれも無検証で継承している部分）

RQ は RQ1（追試）/ RQ2（層別形状）を主軸、RQ3（符号変化と不安定性の相関）/
RQ4（平滑分母 `1+√(ε+A²)`）/ RQ5（pre-activation の区間超過）を副軸に再編。

### 各論文から読み取った実装上の要点

**RAFT**
- safe PAU をそのまま採用。**m=5, n=4**。GELU を **[-3,3]** で fit して初期化
- 探索範囲は m, n ∈ {4, 5} のみ。[-3,3] での GELU 近似が「perfectly fits」なので採用、
  という理由づけ。**近似区間の広さ自体は検討されていない**
- FFN の活性化のみ置換（FFN の構造自体は変えない）。我々の設計と同じ
- **有理係数に別の学習率を使っている**: `lr_θ = 7e-4`（線形減衰）に対し
  `lr_RAF = 5e-3`（warmup 後は**定数**）。予備実験で定数の方が良かったと明記。
  → Phase 1 で我々も有理係数の学習率を分けるべき。**これは知らないと踏む地雷**
- 学習規模: batch 4096、23k ステップ、A100×4 で 12〜16 時間

**KAT**
- safe PAU を基底として採用。**m=5, n=4**。Horner 法で評価（我々と同じ）
- 明示的な勾配式 (Eq.13) に `∂F/∂b_n = a x^n · A(x)/|A(x)| · P(x)/Q(x)²` とあり、
  **`sign(A(x))` が勾配に直接現れる**。A が符号を変えなければこの因子は定数であり、
  勾配は実質平滑。**我々の Day 1 の発見と完全に整合する**
- グループ間で分母係数 b を共有し、分子 a はグループごとに変える
- variance-preserving initialization（gain α = E[F²]/Var[x] を数値推定して w を初期化）
- ablation: GELU 72.7 / PAU 73.6 / KAT-T 74.6
- **スループットは GELU より低い**（2313 vs 2643 batch/s）。CUDA 実装でも遅い
  → 旧 RQ4（推論速度）は追試の価値が低いのでスコープ外に

### 実装照合: RAFT の式(1)は誤植だった【重要】

3本の論文で分母の定義が食い違っていた。

| 出典 | 分母の内側の多項式 | 定数項 |
|---|---|---|
| Molina Eq.(2) | `Σ_{k=1}^{n} b_k x^k` | **なし** |
| KAT Eq.(12) | `b_1x + … + b_nx^n` | **なし** |
| **RAFT Eq.(1)** | `Σ_{k=0}^{n} b_k x^k` | **あり（食い違い）** |

これは重大な差である。定数項があると `A(0) = b_0 ≠ 0` となり、
**Day 1 の発見（折れ点が x=0 に固定される）が成立しなくなる**ため。

→ RAFT の公開リポジトリ (UKPLab/2022-RAFT) を確認したところ、
有理活性化は自前実装ではなく **`ml-research/rational_activations` パッケージに依存**していた。
そのパッケージの実装 (`rational/torch/rational_pytorch_functions.py`) は:

```python
denominator = xps[:, 1:len_deno+1].mul(weight_denominator).sum(1).abs()
return numerator.div(1 + denominator).view(x.shape)
```

`xps[:, 1:...]` と列0（= x⁰）を明示的に飛ばしており、
**実装は `1 + |b_1x + … + b_nx^n|`、すなわち定数項なし**。

**結論: RAFT 論文の式(1)の `k=0` は印字上の誤り（配列添字の 0 始まりを
そのまま数式に書いたものと思われる）。3本とも実装は同一であり、
我々の実装も一致している。Day 1 の発見はそのまま有効。**

### この方針変更が Phase 0 に与える影響

- Phase 0 の作業内容自体は**変更なし**。近似解析は追試にも分母設計の検討にも必要
- ただし **[-3,3] の併記の重要性が上がった**。RAFT が [-3,3] で fit しているので、
  追試のベースラインを正しく再現するには [-3,3] の係数が必須
- T5（pre-activation の [-3,3] 超過率）の位置づけも上がった。
  RAFT の設計判断が decoder-only で妥当かを問う直接の材料になる

### 所感（ポートフォリオとしての評価）

新規性の主張は失ったが、**むしろ扱いやすくなった**と考える。
「先行研究を見落として独自性を主張する」のが最悪であり、
「先行研究を正確に読み、式の誤植を実装レベルで検証し、未検証の条件で追試する」は
研究遂行能力の証明として十分に強い。実際 Day 1 の発見（絶対値が発動しない）は、
3本の論文が誰も指摘していない点である。

## 2026-08-16 | Phase 0 | Day 1(前倒し): PAU 論文 Table 6 の検算ゲート → **PASS**

### 結果

`scripts/verify_table6.py` により、論文 Appendix Table 6 の
Sigmoid / Tanh / Swish の [5,4] 次係数 **30個すべてを記号計算で厳密再現**した。
Swish 列はパラメータ β について記号的に一致（`a2=β/4, a3=3β²/56, b2=3β²/28, b4=β⁴/1680`）。

→ **論文の定義の読み取りが正しいことが確定した。以降の作業に進んでよい。**

### 確定した定義（以降すべてこれに従う）

論文 Eq.(2) の safe PAU:

```
F(x) = P(x)/Q(x) = (Σ_{j=0}^{m} a_j x^j) / (1 + |Σ_{k=1}^{n} b_k x^k|)
```

- **m = 分子次数、n = 分母次数**（"[5,4]" は m=5, n=4）
- **分母の多項式 A(x) に定数項はない**（k は 1 から始まる）
- したがって PAU[5,4] のパラメータ数 = (m+1) + n = 6 + 4 = **10**
  （research_context §3.1 の「1層あたり10個程度」と一致）
- 分母の下限は `Q(x) ≥ q = 1`。論文は q ∈ (0,1) も「勾配増幅の可能性があるが future work」としている

### 計画に影響する発見（3件）

**(1) Table 6 に GELU 列がない。** 列は Sigmoid / Tanh / Swish / ReLU / LReLU(各種) のみ。
→ 検算対象は **Swish (= SiLU)** とする。研究の主目標である GELU 系は論文に対応表がないので、
自前計算の値をそのまま使う（検算は Swish で担保できているのでリスクは低い）。
参考として Padé[5/4]@0 を計算済み:

| 目標 | a (a0..a5) | b (b1..b4) |
|---|---|---|
| silu | 0, 0.5, 0.25, 0.05357143, 0.00595238, 0.00029762 | 0, 0.10714286, 0, 0.00059524 |
| gelu_tanh | 0, 0.5, 0.39894228, 0.23514072, 0.12079567, 0.02659834 | 0, 0.47028144, 0, 0.05319667 |
| gelu_erf | 0, 0.5, 0.39894228, 0.21428571, 0.10448488, 0.02321429 | 0, 0.42857143, 0, 0.04642857 |

**(2) 論文の初期化は2種類の手法が混在している。** Appendix A.1 より:
- Sigmoid / Tanh / Swish → 「standard techniques」＝ **x=0 での真の Padé 近似**（局所構成）

これは Phase 0 の計画で立てた「真の Padé と区間フィットは別物」という区別が
論文自身の中にも存在することの裏付けになる。
また **論文の区間は [-3,3] であり、research_context が想定する [-6,6] より狭い**。

**(3) Padé@0 初期化の裾は SiLU と定性的に食い違う。**

→ **論点A（裾の挙動）の懸念が、論文の公式初期化係数そのもので実証された。**

## 2026-08-22 | Phase 0 | Day 3-b: 折れ点判定の偽陽性処理（Day 2 の再訂正）

### Day 2 の「12/20」も過大計上だった

Day 2 で「区間外を含めると 12/20 の条件で符号変化」と記録したが、
検出された符号変化の大半は **x ≈ ±7.5e-05、傾き |A'| ≈ 2e-05** という
**数値誤差由来の偽陽性**だった。

原因: GELU/SiLU の最適な分母は理論上ほぼ偶関数（`b₁ = b₃ = 0`）だが、
非線形最小二乗の解には `b₁ ~ 1e-7` 程度の残差が乗る。すると原点近傍で
`A(x) ≈ b₁x + b₂x²` となり、`x = -b₁/b₂ ~ 1e-7` に見かけの符号変化が生じる。

`AbsDenominator.kinks()` に2段の処理を入れた:
1. **係数のノイズ除去**: `max|b|` に対し相対 1e-6 以下の係数を 0 とみなす
2. **折れの強さでの足切り**: `|A'(x₀)| > 1e-3`
   （折れ点では定義により `A(x₀)=0` すなわち `Q(x₀)=1` なので、`|A'(x₀)|` は
   そのまま「Q=1 に対する微分の跳びの相対的大きさ」になる。絶対閾値でよい理由）

偽陽性 ~2e-05 と真の折れ点 1.35〜3.84 は **5桁離れており**、閾値の選び方に結果は鈍感。

### 確定した数字

| | フィット区間内 | 区間外を含む [-15,15] |
|---|---|---|
| `abs` の**真の**折れ点がある条件 | **0 / 20** | **2 / 20** |
| `free` の極がある条件 | **0 / 20** | **2 / 20** |

真の折れ点・極があるのは以下の2条件のみで、**どちらも同じ条件**（`A` が負に振れるという
同一の現象が、`A=0` で折れ、`A=-1` で極になる）:

| 条件 | 折れ点 x₀ | \|A'(x₀)\| | 極 x |
|---|---|---|---|
| gelu_tanh [5,4] on **[-3,3]**（RAFT の設定） | ±4.545 | 1.35 | ±5.099 |
| gelu_tanh [6,5] on [-6,6] | ±8.721 | 3.84 | ±8.964 |

silu は全条件で真の折れ点なし。

**Day 1 → Day 2 → Day 3 と2回訂正したが、最終的な結論は Day 1 の直観に近い**:
絶対値は「ほとんどの場合・ほとんどの場所で」不活性。
ただし「一部の条件で・区間外で」は確かに活性化し、そこでは極の回避に効いている。

## 2026-08-22 | Phase 0 | Day 3-c: sqrt 分母の ε スイープ（ユーザー承認の2条件で判定）

`scripts/run_phase0_eps.py` + `configs/phase0_eps.yaml`。96 条件。

### 測定設計上の注意（途中で修正した点）

当初は「独立にフィットした sqrt」と「abs」を比較していたが、
**両者が別の極小解に落ちた分の差まで混ざり**、`max|diff|` が 231 や 896 になった。
ε の効果だけを分離するため、**abs の係数を固定したまま分母の形だけ差し替える**方式に変更。

### 結果（gelu_tanh [5,4] on [-3,3]、RAFT の設定）

| ε | sup 誤差 | abs 比 | 平滑化幅 √ε/\|A'\| | 折れ点での変化量 | \|x\|<1 での変化量 |
|---|---|---|---|---|---|
| 1e-1 | 1.49e-3 | 1.78× | 0.234 | 1.285 | 0.128 |
| 1e-2 | 2.52e-3 | 3.00× | 0.074 | 0.485 | 0.024 |
| **1e-3** | **1.64e-3** | **1.95×** | **0.023** | **0.163** | **0.004** |
| 1e-4 | 9.27e-4 | 1.11× | 0.0074 | 0.051 | 0.0007 |
| 1e-6 | 8.61e-4 | 1.03× | 0.00074 | 0.004 | 0.0000 |

**変化量の最大値は全 ε で x = 4.545、すなわち折れ点ちょうど**に出る。
平滑化は狙いどおり折れ点に効いており、それ以外の場所での変化は小さい。

### 判定: 2条件は「かろうじて」両立する。ただし本質的な限界がある

- **上限（精度）**: ε ≤ 1e-3 なら sup 誤差は abs の 2 倍以内に収まる。ε=1e-2 で 3 倍。
- **下限（意味のある平滑化）**: ε=1e-4 以下では折れ点での変化量が 0.05 以下となり、
  実質 abs と区別できない。ε=1e-3 なら 0.163（関数値のオーダーが 1 なので約16%）。

→ **ε = 1e-3 を採用する。** 両条件を満たす唯一の桁。

**ただし、より本質的な限界を明記しておく必要がある**:

折れ点は `|x| ≈ 4.5` にあり、そこに到達する pre-activation は **9.1e-4（1トークンあたり33.7個）**
しかない。平滑化幅は `√ε/|A'| = 0.023`、分布スケール std=0.924 の **2.5%** にすぎない。
幅を分布スケールと同等にするには `ε ~ |A'|² ~ 1.8` が必要だが、
それは精度を完全に破壊する（ε=0.1 ですでに 1.8 倍悪化）。

実測分布の質量配分:

| 範囲 | 質量 |
|---|---|
| \|x\| < 1 | 5.10e-01 |
| 1 ≤ \|x\| < 2 | 3.56e-01 |
| 2 ≤ \|x\| < 3 | 1.17e-01 |
| 3 ≤ \|x\| < 4.54 | 1.59e-02 |
| **4.54 ≤ \|x\| < 6（折れ点の領域）** | **6.55e-04** |
| 6 ≤ \|x\| < 15 | 2.36e-04 |

### この結果からの Phase 1 への事前予測（重要）

> **R3/R4（平滑分母）と R1/R2（PAU）の差は、初期化時点では
> 1トークンあたり約34個（全体の0.09%）の活性化にしか及ばない。
> したがって perplexity に見える差は出ない可能性が高い。**

これは**実験前に立てられる定量的な予測**であり、Phase 1 の結果解釈の基準になる。
- 差が出なければ → 予測どおり。機構つきで説明できる（「そもそも効く場所を通らない」）
- 差が出れば → 予測に反する。裾の少数の活性化が不釣り合いに効いているということで、
  それ自体が面白い発見になる

**また、この予測は「初期化時点」の話であることに注意。** 学習中に係数が動いて
`A` が分布の中心付近で符号を変えるようになれば話は変わる。
それを検出するのが RQ3 の毎ステップ診断（符号変化数の記録）であり、
**Phase 1 でその診断を入れる動機がここで定量的に裏付けられた。**

### 結果2【重要な訂正】: 条件数の悪化は**順伝播の精度には効かない**

Day 2 に「[-6,6] では m=7 で float32 の有効桁を5〜6桁失う」と書いたが、
**これは順伝播の評価精度の話ではなかった。** 実測:

| m | 条件数 [-3,3] | 条件数 [-6,6] | float32 相対誤差 [-3,3] | float32 相対誤差 [-6,6] |
|---|---|---|---|---|
| 5 | 2.0e+02 | 4.4e+03 | 2.7e-07 | 3.8e-07 |
| 7 | 2.7e+03 | 1.6e+05 | 3.7e-07 | 1.0e-06 |
| 11 | 5.8e+05 | 2.8e+08 | 3.7e-07 | 7.5e-07 |
| 13 | 9.0e+06 | **1.2e+10** | 3.8e-07 | 9.8e-07 |

条件数が **1.2e10** の条件でも float32 相対誤差は **1e-6** に留まる。

理由: Vandermonde の条件数が支配するのは**係数を決める問題（フィッティング）**であり、
係数が与えられた後の **Horner 評価は後退安定**なので条件数では増幅されない。

**正しい言い方**: 条件数が効くのは**学習ダイナミクス**である。
`x=6` では `x^5 = 7776` なので、係数 `a_j` ごとに勾配の大きさが桁で違う
（`∂F/∂a_j = x^j/Q`）。これは損失曲面の悪条件化であって、順伝播の桁落ちではない。

→ **Phase 1 で R2/R4（広区間）が不安定になった場合、疑うべきは
順伝播の精度ではなく最適化（勾配スケールの不均衡）である。**
学習率や勾配クリッピングの問題として扱うのが正しい。

### 結果4: Horner 法の利点は精度ではなく演算数

8. **Padé@0（論文どおりの初期化）は広区間で破綻する。** [-6,6] で区間フィットの約280倍悪い。
9. **条件数の悪化は順伝播の精度に効かない。** cond=1.2e10 でも float32 相対誤差は 1e-6。
   効くのは係数決定と学習ダイナミクス（勾配スケールの不均衡）。
10. **ε=1e-3 が精度の上限条件と平滑化の下限条件を同時に満たす唯一の桁。**
11. **差し替え条件下では、近似区間の選択が分母設計より圧倒的に支配的。**
    ただし **9 と 11 は「係数凍結」という強い前提の下でのみ成立する**（下記の限界を参照）。

### Phase 0 の限界（Phase 1 に持ち込んではいけないもの）

- **差し替え実験は学習を伴う結果を予測しない。** R1 = RAFT の設定を破滅的と判定するが、

## 2026-08-22 | Phase 1 | Pre-registration: 判定基準・安定化方針・発散時の扱い

**Stage 0 着手前に確定する。以後、結果を見てから変更しない。
変更が必要になった場合は変更理由とともに報告する。**
（Phase 0 で折れ点の定義を Day 1→2→3 と2回訂正した反省を踏まえた措置。）

### 1. RAFT との既知の乖離（DeepNorm 非対称性）

RAFT は勾配クリッピングを使わず（Table 10: Gradient clipping = 0）、
代わり **DeepNorm 初期化**（Wang et al., 2022）で学習を安定化している。
論文 p13 に「`lr_θ=7E-4` かつ batch size **2048**（RAFT 本番の半分）では
モデル更新が不安定になり、DeepNorm を使わざるを得なかった」と明記されている。

本実装には DeepNorm がない。かつ我々のバッチ（1ステップ 8,192〜16,384 トークン）は
RAFT 本番（524,288 トークン）の **32〜64分の1**であり、RAFT 自身が「不安定化した」
と報告した設定（バッチ半分）よりさらに極端に小さい。

**したがって安定化機構が非対称になる**: RAFT は DeepNorm で安定化、我々は
勾配クリッピングで安定化。これは「設定を厳密に揃える」という追試の原則から
外れる。**ただしこの乖離を受け入れる。** 理由:
- DeepNorm をこの規模で実装・検証すること自体が Phase 1 の主目的から外れる
  （research_context §9 スコープ外「新規アーキテクチャの提案」に抵触しうる）
- 安定化機構を一切持たないまま実行し、発散の都度デバッグする方が
  10.5時間の予算を無駄にするリスクが高い
- 勾配クリッピングは**クリップ前のノルムを記録すれば**不安定性の診断量として
  機能を失わない（下記3.参照）

### 2. 勾配クリッピングの採用（決定）

**採用する。** グローバルノルムクリップ、閾値 **1.0**、**全条件（B1/B2/R1〜R4）で同一設定**。

- 理由は上記1.のとおり。RAFT との差分として明記済みなので、
  「RAFT を再現できなかった」場合にこの差分を要因の候補として挙げられる。
- 閾値 1.0 は nanoGPT 系ミニマル実装の一般的な既定値。
  Stage 0 の疎通確認で極端な値でないことを確認する。
- **RQ3/RQ4 の不安定性診断には、クリップ前の生の勾配ノルムを使う。**
  クリップ後のノルムは定義上つねに閾値以下になり、診断量として無意味になるため。

### 3. 「学習が不安定」の判定基準

- **損失スパイク**: ある学習ステップの loss が、直前 window=100 ステップの
  移動平均 + 5×移動標準偏差 を超えた場合。異常検知の標準的な形。
- **発散**: 以下のいずれかが成立した場合。
  - loss が NaN または Inf になる
  - loss が `2 × ln(vocab_size)`（vocab=8192 の場合 `2×9.01 ≈ 18.0`）を
    連続10ステップ超える（= ランダム推測の2倍のクロスエントロピーが持続する）
  - **クリップ前**の勾配ノルムが、直前100ステップの移動中央値の **20倍**を超える
- **勾配ノルムの傾向的な悪化**: クリップ前ノルムの移動中央値が、
  学習全体を通じて単調に増加し続ける場合（発散の前兆として記録するが、
  それ自体は不安定の確定条件ではない）。

### 4. 「条件間に差がある」の判定基準

CLAUDE.md の方針（統計的仮説検定は不要、seed 間のばらつきを示せば十分）に従い、
**seed 3本のレンジが重ならないこと**を「差がある」の基準とする。

> 条件 A と条件 B のある指標（validation perplexity, 符号変化数, 等）について、
> `min(A の3 seed) > max(B の3 seed)` または `min(B の3 seed) > max(A の3 seed)`
> が成立するとき、かつそのときに限り「差がある」と判定する。

レンジが重なる場合は「差があるとは言えない」として扱い、無理に優劣を主張しない。
これは検定ではなく**素朴で透明な非重複基準**であり、CLAUDE.md の「有意差検定は不要」
という方針と整合する。

### 5. 記録する診断量（確定リスト）

**毎ステップ**:
- training loss、**クリップ前**の勾配ノルム（global norm）

**評価タイミングごと（例: 500 ステップごと）**:
- validation loss / perplexity
- 各層の pre-activation 分位点（0.1%, 1%, 50%, 99%, 99.9%, min, max）— RQ5
- 各層の `A(x)` の符号変化数（`RationalActivation.count_sign_changes()`）— RQ3
  （B1/B2 では該当なし。R1〜R4 のみ）

**学習後（1回）**:
- 各層の有理関数の形状（[-15,15] でプロット）— RQ2
- tokens/sec、ピークメモリ（参考値）

### 6. 発散時の扱い（原則）

**発散した条件の学習率だけを下げて救済しない。** 理由: それをすると
条件間で設定が揃わなくなり、比較そのものが無効になる。

手順:
1. ある条件が上記3.の発散基準に達したら、そのステップで学習を打ち切り、
   「この設定では発散した」という結果として記録する（削除・やり直しの対象にしない）。
2. 複数条件、または B1（ベースライン）が発散した場合、**全条件で lr_θ を
   一律に下げ直し、そのステージ全体をやり直す**ことを検討する。
   ただしこれは新たな長時間ジョブの再実行にあたるため、
   CLAUDE.md の資源管理ルールに従い、**新しい見積もりを提示してユーザーの
   承認を得てから**実行する。自動では再実行しない。
3. R1〜R4 の一部のみが発散し B1/B2 は安定している場合、
   それ自体が RQ3/RQ4 に対する結果である可能性が高い（分母設計・近似区間が
   学習を不安定化させた、という直接的な証拠）。安易に「設定が悪かった」と
   片付けず、まず発散の直接原因（符号変化・勾配ノルムの推移）を確認する。

→ **有理活性化は勾配を系統的に増幅しており、R1 は安定性の境界上にある。**
3 seed のうち 2 つは越えず、1 つが越えた。これは RQ3/RQ4 に対する直接的な観測。

### RQ3: 学習中に `A(x)` の符号変化は実際に発生した

初期値は全層 `[2,2,2,2,2,2]`（Phase 0 Day 3 の予測どおり）。学習が進むと変動する:

- seed=0: `[2,2,2]` → `[1,2,3]` → `[1,1,4]` → …（層ごとに独立に増減）
- seed=1: `[2,2,2]` → `[2,4,1]` → `[2,2,1]` → …
- seed=2: `[2,2,2]` → `[1,4,4]` → `[1,4,3]` → `[1,2,4]`（発散まで）

**符号変化数は固定ではなく、学習を通じて層ごとに動く。**
Phase 0 で「学習中に符号変化が発生するか」を RQ3 の核心に据えた判断が、
実データで裏付けられた。値が増える層と減る層の両方がある。

**注意**: 現時点では「符号変化の増加が発散を引き起こした」とは言えない。
seed=2 の発散直前の符号変化 `[1,2,4]` は seed=0 の安定時の値と大差ない。
発散との因果は R2〜R4 まで揃えてから改めて検討する。

### 完走した seed の perplexity はベースラインと同等

seed0=5.535, seed1=5.618。B1 レンジ [5.575, 5.627]、B2 レンジ [5.534, 5.587]
と重なる。**発散しなかった限りにおいては、RAFT の設定でも perplexity は
ベースラインと差がない**（ただし seed が1つ欠けており、3 seed 揃った比較ではない）。

### RQ5: pre-activation の裾は学習中に育つか → **育つ。しかも [-6,6] すら超える**

ユーザーの事前指摘（「学習初期は LayerNorm 直後でほぼ正規分布、裾は後から育つ」）が
**そのまま確認された**（seed0、全層の最大値）:

| step | B1 max\|x\| | B1 q99.9 | R1 max\|x\| | R1 q99.9 | R2 max\|x\| | R2 q99.9 |
|---|---|---|---|---|---|---|
| 0 | 2.22 | 1.22 | 2.22 | 1.22 | 2.23 | 1.22 |
| 600 | 7.76 | 2.97 | 7.58 | 3.59 | 7.54 | 3.66 |
| 6600 | 12.24 | 4.89 | 13.34 | 6.22 | 13.87 | 6.22 |
| 12199 | 14.26 | 4.89 | 14.42 | 5.95 | 15.80 | 6.24 |

- **step 0 では max|x| = 2.22 で [-3,3] に完全に収まっている**（予測どおり）
- **step 600 で既に max|x| ≈ 7.6 と [-6,6] を超える**
- 最終的に max|x| ≈ 14〜16、**99.9%点も 6.0〜6.2 と [-6,6] の境界に達する**

→ **research_context §10 の「小規模モデルでは重い裾が育たないかもしれない」
というリスクは現実化しなかった。** 13.8M パラメータ・TinyStories でも裾は育つ。

**有理条件（R1/R2）の方が GELU より裾が重い**（q99.9 が 5.95〜6.24 vs 4.89）。
活性化関数と重みが相互作用した結果と考えられるが、機構は特定できていない。

| val_ppl レンジ | [5.535, 5.618] | [5.566, 5.639] | [5.591, 5.665] | [5.610, 5.648] |

- 発散は R1 のみ（1件）。方向としては平滑分母に有利だが **1/3 vs 0/3 は
  seed 3本では偶然と区別できない**
- 損失スパイクは R3 のみ 0 だが、他条件も 1 件ずつで差とは言えない
- **勾配ノルムはむしろ R1 が最も低く、仮説と逆方向**
- perplexity に差はない

→ **「平滑分母が安定性を改善する」という主張は、この実験では支持されない。**
唯一の発散事例が R1 に出たことは示唆的だが、それだけで結論するのは不適切。
**否定的結果として報告する。**
