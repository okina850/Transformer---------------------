  venv は小ファイルが大量にできるため、Drive 同期に載せると同期が重くなる。

`torch==2.13.0+cu130` は `gpif` と同じホイールを明示指定した

- GPU 情報の取得は `include_gpu` フラグで切れるようにした。
  Phase 0 の近似計算部分は numpy のみで完結し、torch の import（数秒）が無駄になるため。

### 決まったこと（Phase 0 のスコープ確定）

ユーザー承認により以下が確定した。

- **論点A（裾の挙動を揃えた変種を追加）: 採用。**
  `Q(x)=1+A(x)²` は分母の実効次数が `2m` になるため、同じ `(n,m)` を使うと
  PAU 型は両側で線形発散、平滑型は両側で 0 に減衰と、**近似する関数クラスが別物になる**。
  これを揃えないと Phase 1 で平滑型が負けたとき、原因が「平滑性」か「裾の形」か切り分け不能。
  → `deg P = 2m+1`（`deg P − deg Q = 1` を保つ）変種も誤差評価する。
- **論点B（GPT-2 実測 pre-activation 密度による重み付き近似）: Day 7 の余力タスクに格下げ。**
  理由: Phase 1 はスクラッチ学習であり、学習初期の pre-activation 分布は GPT-2 のそれと
  異なるため、この重みで作った係数を Phase 1 の初期化にそのまま使えない。
  1週間の成果物としての優先度が低いという判断。
- 計算コスト見積もり承認（GPU 使用は最大 30〜40分。**まず1条件で通してから全条件に上げる**）。
- seed の扱い承認: Phase 0 は学習がなく決定論的なので、
  非線形最小二乗の**初期値を3通り試して同一解に収束することを確認**する形で

## 2026-08-16 | Phase 0 | Day 1(前倒し): PAU 論文 Table 6 の検算ゲート → **PASS**

### 結果

`scripts/verify_table6.py` により、論文 Appendix Table 6 の
Sigmoid / Tanh / Swish の [5,4] 次係数 **30個すべてを記号計算で厳密再現**した。
Swish 列はパラメータ β について記号的に一致（`a2=β/4, a3=3β²/56, b2=3β²/28, b4=β⁴/1680`）。

→ **論文の定義の読み取りが正しいことが確定した。以降の作業に進んでよい。**

### 確定した定義（以降すべてこれに従う）

論文 Eq.(2) の safe PAU:

```
F(x) = P(x)/Q(x) = (Σ_{j=0}^{m} a_j x^j) / (1 + |Σ_{k=1}^{n} b_k x^k|)
```

- **m = 分子次数、n = 分母次数**（"[5,4]" は m=5, n=4）
- **分母の多項式 A(x) に定数項はない**（k は 1 から始まる）
- したがって PAU[5,4] のパラメータ数 = (m+1) + n = 6 + 4 = **10**
  （research_context §3.1 の「1層あたり10個程度」と一致）
- 分母の下限は `Q(x) ≥ q = 1`。論文は q ∈ (0,1) も「勾配増幅の可能性があるが future work」としている

### 計画に影響する発見（3件）

**(1) Table 6 に GELU 列がない。** 列は Sigmoid / Tanh / Swish / ReLU / LReLU(各種) のみ。
→ 検算対象は **Swish (= SiLU)** とする。研究の主目標である GELU 系は論文に対応表がないので、
自前計算の値をそのまま使う（検算は Swish で担保できているのでリスクは低い）。
参考として Padé[5/4]@0 を計算済み:

| 目標 | a (a0..a5) | b (b1..b4) |
|---|---|---|
| silu | 0, 0.5, 0.25, 0.05357143, 0.00595238, 0.00029762 | 0, 0.10714286, 0, 0.00059524 |
| gelu_tanh | 0, 0.5, 0.39894228, 0.23514072, 0.12079567, 0.02659834 | 0, 0.47028144, 0, 0.05319667 |
| gelu_erf | 0, 0.5, 0.39894228, 0.21428571, 0.10448488, 0.02321429 | 0, 0.42857143, 0, 0.04642857 |

**(2) 論文の初期化は2種類の手法が混在している。** Appendix A.1 より:
- Sigmoid / Tanh / Swish → 「standard techniques」＝ **x=0 での真の Padé 近似**（局所構成）
- ReLU / LReLU 系 → **[-3, 3] 上の最小二乗フィット**（区間構成）

これは Phase 0 の計画で立てた「真の Padé と区間フィットは別物」という区別が
論文自身の中にも存在することの裏付けになる。
また **論文の区間は [-3,3] であり、research_context が想定する [-6,6] より狭い**。

**(3) Padé@0 初期化の裾は SiLU と定性的に食い違う。**
SiLU の Padé[5/4]@0 は `b = [0, 3/28, 0, 1/1680]` なので
`A(x) = (3/28)x² + (1/1680)x⁴ ≥ 0`、よって `Q = 1+|A| = 1+A`。
このとき `x→±∞` で `F(x) ~ (a5/b4)x = (1/3360)/(1/1680) x = x/2`、
つまり **左裾で −∞ に発散する**。SiLU は `x→−∞` で 0 に収束するので、
近似区間の外で定性的に破綻している。

→ **論点A（裾の挙動）の懸念が、論文の公式初期化係数そのもので実証された。**
Phase 0 で近似区間外の挙動を測る意義が確認できた。

### 副産物: Table 6 の誤植疑い

論文表の Sigmoid `b4` は `1/10008` と印字されているが、真の Padé 近似は **`1/1008`**
（1/1008 ≈ 9.92e-4 に対し 1/10008 ≈ 9.99e-5 で1桁違う）。
桁の誤植と判断した（PDF テキスト抽出の乱れの可能性も否定できないが、
Sigmoid は本研究の目標関数ではないため影響はない）。

### 実装メモ

- 係数配列は**昇順で統一**（`coeffs[j]` が `x^j` の係数）。論文の記法と一致させ、
  表とそのまま突き合わせられるようにするため。numpy の `polyval` は降順なので注意。
- `poly.py` に Horner 法と素朴評価の両方を用意した（T4 の精度比較用）。
  Vandermonde の条件数も測れるようにした（§5.3 の重心形式の着手条件の判定材料）。
- 目標関数は `gelu_erf` と `gelu_tanh` を別物として実装。
  GPT-2 が使うのは `gelu_tanh`（`gelu_new`）なので、差し替え実験ではこちらを目標にする。
