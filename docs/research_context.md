## 2. 研究テーマ

**学習可能な有理活性化関数の decoder-only Transformer における追試と、分母設計の検討**

### 一行要約
encoder-only Transformer (BERT系) で有効性が報告されている学習可能有理活性化関数を、
decoder-only の自己回帰言語モデルで追試する。あわせて、先行研究がいずれも無検証で継承している
safe PAU の分母設計 `1+|A(x)|` を数値解析の観点から検討する。

## 3. 背景と先行研究

### 3.1 学習可能有理活性化関数とは
活性化関数を有理関数 F(x) = P(x)/Q(x) で表現し、係数をネットワークの重みと一緒に
誤差逆伝播で学習させる手法。層ごとに最適な非線形性の形状を自動獲得できる。
パラメータ増加はごくわずか（PAU では1層あたり10個程度）。

### 3.2 既知の先行研究（`docs/refs/` 配下の PDF を参照）

| 文献 | 内容 | 検証対象 |
|---|---|---|
| **Molina et al., ICLR 2020** (`pade_activation.pdf`) | Padé Activation Unit (PAU) を提案。安全化のため分母を `Q(x) = 1 + \|Σ_{k=1}^{n} b_k x^k\|` とし極を回避。次数[5,4]（m=5, n=4）、層ごとに1つの PAU を共有。既知活性化の Padé 近似係数で初期化。区間フィットは **[-3,3]** | CNN 画像分類 |
| **Boullé et al.** (`rational_NN.pdf`) | 低次数 type (3,2) の有理活性化。合成により実効次数が指数的に増える点を理論的に示す。**PAU の絶対値による非平滑性と勾配計算コストを明示的に批判** | PDE 求解、GAN |
| (`rational_activation_function.pdf`) | 一様ノルム（minimax）ベースの損失で有理活性化を学習。準凸最適化・二分法・差分修正法。低次数(1,1) | 分類タスク |
| **★RAFT: Fang, Lee, Moosavi, Gurevych (arXiv:2208.14111v3, 2023)** (`Transformers_with_Learnable_Activation_Functions.pdf`) | safe PAU をそのまま採用（m=5, n=4、GELU を **[-3,3]** で fit、GELU 近似で初期化）。**encoder-only Transformer (BERT系, 12層, hidden 768, 12ヘッド) を English Wikipedia + MLM でスクラッチ事前学習**。RAFT は FAFT より低い validation perplexity を達成し、GLUE・SQuAD で上回る。**層ごと・タスクごとの学習後形状も可視化・分析済み**。コード公開 (UKPLab/2022-RAFT) | **encoder-only 言語モデル** |
| **★KAT: Yang & Wang (NUS)** (`Kolmogorov_ArnoldTransformer.pdf`) | KAN の基底関数を B-spline から有理関数に置換。**safe PAU を基底として採用**（m=5, n=4）。グループ間で分母係数 b を共有し分子 a はグループごとに変える。variance-preserving initialization（gain α = E[F²]/Var[x] を数値推定して w を初期化）。CUDA 実装。ablation: GELU 72.7 / PAU 73.6 / KAT-T 74.6。**スループットは GELU より低い（2313 vs 2643 batch/s）** | Vision Transformer |

### 3.3 何が既知で、何が未検証か（本研究の立脚点）

**既に answered（追試の対象）**
- 有理活性化が Transformer 言語モデルで GELU を上回りうるか → RAFT が encoder-only で肯定的に報告
- 学習後の形状が層ごとに異なるか → RAFT・KAT の両方が報告
- 有理活性化は GELU より速いか → KAT が **否定的**に報告（CUDA 実装でも遅い）

**未検証（本研究が扱う）**
1. **decoder-only の自己回帰言語モデルでの検証。** RAFT は encoder-only (MLM)、KAT は vision。
   KAT 自身が future work で「言語モデルへの応用」を挙げており、この設定は空いている。
   ただし「encoder でやったことを decoder でもやった」は新規性としては弱いので、
   **追試（replication）として正面から位置づける**。
2. **分母設計 `1+|A(x)|` の妥当性。** PAU 以降、RAFT も KAT も**無検証でそのまま継承**している。
   Boullé et al. は非平滑性を批判し、KAT は limitations で
   「a_m と b_n の高階勾配が入力のべき乗に依存するため不安定になりうる」と明記している。
   つまり**複数の独立した論文が同じ弱点を認識しているが、誰も対処していない**。
3. **近似区間 [-3,3] の妥当性。** PAU も RAFT も [-3,3] で fit している。
   Phase 0 の実測により、この設定では区間外で公式初期化係数が発散することを確認済み。
   decoder-only LM の pre-activation が [-3,3] に収まるかは未検証（T5 で測定する）。

## 4. リサーチクエスチョン

### 主軸: 追試（確実に完了させる）

- **RQ1**: RAFT が encoder-only で示した「有理活性化 > GELU」という結果は、
  **decoder-only の自己回帰言語モデルでも再現されるか。**
- **RQ2**: 学習後の有理関数の形状は層ごとに異なるか（RAFT・KAT の観察が decoder-only でも成立するか）。

### 副軸: 未検証部分の探索（余力に応じて）

- **RQ3**: safe PAU の絶対値による非平滑性は、実際に問題を引き起こすか。
  Phase 0 の発見（下記 §5.2）を踏まえ、**学習中に `A(x)` の符号変化が発生するか、
  発生した場合に損失スパイク・勾配ノルム急増と相関するか**を検証する。
- **RQ4**: 平滑かつ極なしの分母設計（`1+√(ε+A(x)²)`）は、PAU 型と比べて
  学習の安定性・最終性能を改善するか。またその差は次数を上げたときにどう変化するか。
- **RQ5（優先度低）**: pre-activation 分布は [-3,3] に収まるか。収まらない場合、
  区間外の挙動が性能に影響するか。

### 扱わない
- スループット比較（KAT が既に否定的な結論を出しているため、追試の価値が低い）。
  余力があれば参考値として測る程度に留める。

## 5. 本研究の位置づけ

### 5.1 主たる貢献: decoder-only 設定での追試
先行研究の結果を、条件を変えて再現できるかを検証する。単なるコピーではなく、
論文に書かれていない部分（アーキテクチャ、データセット、モデル規模）を自分で埋めて実装する。
**再現研究（replication study）として正面から位置づける。**

### 5.2 独自の検討: 分母設計

**Phase 0 の重要な発見（Day 2 時点。Day 1 の記述を実測に基づき訂正）**:

`Q(x) = 1 + |A(x)|` の `A(x)` は定数項を持たない（k は 1 から始まる）ため `A(0) = 0` が常に成立する。
GELU/SiLU に最適な分母はほぼ偶関数（`b₁ ≈ b₃ ≈ 0`）になるため、
`A(x) ≈ b₂x² + b₄x⁴ + …` となり、**フィット区間の内側では原点で接するだけで符号を変えない**。
したがって区間内では `|A| = ±A` であり、絶対値は何もしておらず、Q は完全に平滑である。

**ただしこれはフィット区間の内側に限った話である。** 測定範囲を [-15,15] に広げると:

| 測定範囲 | `1+\|A\|` の折れ点がある条件 | `1+A` の極がある条件 |
|---|---|---|
| フィット区間の内側 | **0 / 20** | **0 / 20** |
| [-15, 15]（区間外を含む） | **12 / 20** | **2 / 20** |

決定的な例として、`gelu_tanh` を **[-3,3] で [5,4] にフィット**（＝RAFT の設定そのもの）すると、
制約なし分母 `1+A(x)` は **x ≈ ±5.10 に極を持つ**。フィット区間のすぐ外側である。

**この発見が意味すること**:
- **safe PAU の絶対値による安全化は必要である。** 制約を外すと区間のすぐ外に極が出る。
  ただし**それが効いているのは区間の外だけ**であり、区間内では絶対値は恒等的に不活性。
  実際 `1+|A|` と `1+A` は区間内での近似誤差が小数点以下まで完全に一致し、
  **区間外で `A` が符号を変えた点で初めて分岐する**（`F(10)` が −6.24 と +6.47）。
- したがって Boullé et al. の非平滑性批判は「空振り」ではないが、
  **問題になるのは区間外を通ったときだけ**、という限定が付く。
- 折れ点の位置は x=0 に固定されるとは限らない。`b₁ ≈ 0` である限り x=0 では接するだけで、
  実際の符号変化は**区間外で起きている**。学習中に `b₁` が 0 から離れれば x=0 近傍でも起きうるが、
  それは Phase 1 で実測すべき仮説であって、Phase 0 で確認された事実ではない。
- **絶対値・極・裾の破綻は、すべて「フィット区間の外」という一つの論点に収束する。**
  したがって **decoder-only LM の pre-activation が区間外をどれだけ通るか（RQ5 / T5）が、
  分母設計に関する問い全体の前提条件**になる。

**したがって本研究の分母設計に関する問いは次の形になる**:
> (a) decoder-only LM の pre-activation は、フィット区間の外をどれだけ通るか。
> (b) 通るとして、学習中に `A(x)` の符号変化は実際に発生するか。
> 発生する場合、それは損失スパイクや勾配ノルムの急増と相関するか。
> (c) 平滑な分母に置き換えることでそれは回避されるか。

**(a) が否定的（区間外をほとんど通らない）なら、(b)(c) は自動的に「影響なし」となり、
それ自体が明確な結論になる。** その場合、分母設計より近似区間の選び方の方が
本質的だったという報告になる。

**分母設計の選択（重要）**:

| 設計 | 実効分母次数 | 裾 F ~ x^p | 平滑性 | Phase 1 での扱い |
|---|---|---|---|---|
| `1 + \|A(x)\|`（PAU） | n | x¹ | 折れうる | **ベースライン（R1/R2）** |
| `1 + √(ε + A(x)²)` | n | **x¹（PAU と一致）** | C^∞ | **提案手法（R3/R4）** |
| `1 + A(x)²` | **2n** | **x^(m-2n)（0 に減衰）** | C^∞ | **Phase 1 では使わない** |

`1 + A(x)²` は平滑性と裾の**両方**が同時に変わるため、差が出ても原因を切り分けられない。
`1 + √(ε + A(x)²)` は PAU と実効次数も裾も一致し、**違いが平滑性だけ**になるので、
統制された比較として適切である。`1+A²` は Phase 0 の近似誤差比較には残すが、
Phase 1 の学習条件からは外す。

**ε の選定基準（Phase 0 で決める。2条件を同時に満たすこと）**:

`√(ε + A²)` は `A→0` でも `√ε` の下駄を履くため、ε は2方向から挟まれる。

1. **上限**: ε が大きすぎると近似精度の頭打ちを起こす。
   実測で ε=1e-3 は n_params=14 のとき `abs` の 840 倍悪くなった。
   → 「近似精度を落とさない範囲で最大の ε」
2. **下限**: ε が小さすぎると `√(ε+A²) → |A|` となり、**`sqrt` が `abs` に漸近して
   R3/R4 と R1/R2 が区別できなくなる**。平滑化の幅はおおよそ `√ε` なので、
   → 「`√ε` が pre-activation の分布スケールに対して意味のある大きさであること」
   （この判定には T5 の実測分布が必要。だから T5 を先に行う）

**両立しない場合（上限 < 下限）は、それ自体を結論として報告する。**
すなわち「平滑化を意味のある幅で入れると近似精度が犠牲になり、
精度を保つと平滑化が名目上のものになる」というトレードオフの存在自体が知見になる。

## 6. 実験計画

### Phase 0: 事前近似解析（学習不要・**1週間で完了。最初のマイルストーン**）

**進捗**: Day 0（環境整備）完了、Day 1（Table 6 検算 PASS、線形化最小二乗、分母4設計）完了。

1. GELU / SiLU の Padé 近似・区間フィットを次数を変えて計算（型: (3,2), (4,3), (5,4), (6,5) など）。
   近似区間は **[-6,6] を主軸、[-3,3] を併記**（[-3,3] は PAU・RAFT の設定と直接比較するため）。
   - 検証: `docs/refs/pade_activation.pdf` Appendix Table 6 と突き合わせ → **完了・PASS**
2. 各次数での最大誤差・L2誤差を測定し、誤差曲線を作る。
3. 分母4設計（abs / sqrt / square / free）の近似精度・平滑性・裾の挙動を比較。
   **`A(x)` の符号変化数を必ず記録する**（§5.2 の発見の根拠）。
4. 学習済みモデル（GPT-2 small）の FFN 活性化を各近似で置き換え、perplexity 劣化を測定（学習なし）。
   - **論文どおりの Padé@0 初期化**も1条件として含める（PAU の再現性の担保）。
5. **T5: GPT-2 の pre-activation 分布を層ごとに測定し、[-3,3] をどれだけ超えるかを定量化する**（RQ5）。

**成果物**: 次数ごとの近似誤差表、perplexity 劣化曲線、pre-activation 分布図、
Phase 1 で使う初期化係数（`coefficients.json`、**[-3,3] と [-6,6] の両方**）。

#### 【必読】Phase 0 の差し替え実験（項目4）の限界

**Day 5 の差し替え perplexity は、Phase 1 の結果を予測しない。**
Phase 0 の結果を引用するときは必ずこの限界を併記すること。

**決定的な反例が我々自身の結果の中にある。** 条件 R1 は **RAFT 論文と全く同じ設定**
（safe PAU、[5,4]、GELU を [-3,3] でフィット）であり、Day 5 はこれを
perplexity 34,795（基準の1361倍）＝破滅的と判定した。しかし
**RAFT はこの設定で学習させ、GELU ベースラインを上回っている**（PPL 5.00 vs 5.18）。

理由:
1. **Day 5 では係数が凍結されている。** 有理活性化の本質は係数が学習で動くことであり、
   学習中に区間外の挙動も改善されうる。
2. **学習済み GPT-2 の重みは厳密な GELU 用にチューニング済み**なので、ズレはすべて純損害。
   Phase 1 ではモデルが活性化と一緒に学習し、pre-activation が暴れない方向に適応しうる。
3. **平滑分母の主張（§5.2）は「学習中の勾配の安定性」に関するもの**で、
   学習しない実験では原理的に検証できない。
   R4 が R2 に負けたことは **RQ4 について何も語っていない**。

**したがって Day 5 の結果を根拠に Phase 1 の条件を削らないこと。
`coefficients.json` を [-6,6] 単独に絞らないこと。**

Phase 0 の結論は「**差し替え条件下では**区間が支配的だった」であり、
「Phase 1 でもそうなる」ではない。

### Phase 1: decoder-only Transformer の学習と比較（本体）

**モデル**: decoder-only Transformer（nanoGPT 系のミニマル実装ベース）。
10〜30M パラメータ程度。単一 GPU で1条件あたり数時間で回ることを必須要件とする。

**データ**: TinyStories または WikiText-103。まず小さい方で pipeline を確立する。

**比較条件（これで確定。勝手に増やさない）**:

**2×2 の第2軸は「次数」ではなく「近似区間」とする**（Phase 0 Day 3 の結果を受けて変更）。
理由: 平滑分母と PAU の差は初期化時点で全活性化の **0.09%** にしか及ばないと定量的に
予測できたのに対し、近似区間の外に出る活性化は **1.68%（1トークンあたり620個）** と
桁が2つ大きい。次数の効果は Phase 0 の誤差表で既に測れており、
GPU 予算を使う価値が相対的に低い。型は全条件 **[5,4]**（PAU / RAFT / KAT 共通）に固定する。

| 条件 | 分母設計 | 近似区間 | 対応する RQ |
|---|---|---|---|
| B1 | GELU（ベースライン） | — | RQ1 |
| B2 | SwiGLU（ベースライン） | — | RQ1 |
| R1 | safe PAU (`1+\|A\|`) | **[-3,3]** | RQ1, RQ3（**RAFT の完全再現**） |
| R2 | safe PAU (`1+\|A\|`) | **[-6,6]** | RQ1, RQ3, RQ5 |
| R3 | 平滑分母 (`1+√(ε+A²)`, ε=1e-3) | **[-3,3]** | RQ4 |
| R4 | 平滑分母 (`1+√(ε+A²)`, ε=1e-3) | **[-6,6]** | RQ4, RQ5 |

R1 は RAFT・KAT と同一の定式化・同一の近似区間であり、**追試のベースラインを兼ねる**。
ε=1e-3 は Phase 0 の ε スイープで、精度の上限条件と平滑化の下限条件を
同時に満たす唯一の桁として決定した。

**必ず記録すること**:
- **各層の `A(x)` の符号変化数を毎ステップ記録する**（RQ3 の核心。計算コストはほぼゼロ）
- **各層の pre-activation の分位点（0.1%, 1%, 50%, 99%, 99.9%, min, max）を、
  評価タイミングごとに記録する。**
  T5 が測ったのは**学習済み**の GPT-2 の分布である。Phase 1 はスクラッチ学習なので、
  学習初期の pre-activation は LayerNorm 直後にランダム重みを掛けたものであり、
  ほぼ正規分布で**あの重い裾は存在しない**。裾は学習の過程で後から育つ。
  したがって「近似区間の効果がいつ現れ始めるか」という時間軸の情報が必要になる。
  追加コストはほぼゼロ。
- **R1〜R4 の各条件の Vandermonde 条件数を、誤差表に列として記録する。**
  モノミアル基底では区間が [-3,3] → [-6,6] に広がると `x^5` の値域が 243 → 7776 と
  32 倍になるため、条件数は悪化する（Phase 0 実測: m=5 で 2.0e2 → 4.4e3）。
  **区間軸の比較は、近似の質だけでなく数値条件の差も同時に動かしている**ので、
  差が出た場合にどちらの寄与かを議論できるよう実測値を残す。
- 学習曲線（loss vs step）、勾配ノルムの推移、損失スパイクの発生時刻
- 学習後の各層の有理関数形状（RQ2）

**必ず守ること**:
- **有理係数の学習率を RAFT の設定に合わせること。**
  RAFT はモデル本体が `lr_θ = 7e-4`（warmup 後に線形減衰）なのに対し、
  有理係数だけ `lr_RAF = 5e-3`（warmup 後は**定数**）を使っている（論文 §4）。
  約7倍の差があり、スケジュールの形自体も違う。
  **主軸が追試である以上、ここを揃えないと「再現しなかった」ときに
  設定差か本質かを区別できなくなる。** Phase 1 設計時の判断項目として残す。
- **パラメータ数を揃えること。** SwiGLU はゲート構造で行列が1枚多い。d_ff を調整して揃えるか、
  揃えられない場合はその差を明記すること。
- 同一データ・同一ステップ数・同一ハイパーパラメータ探索予算で比較すること。
- 各条件で seed を最低3つ振り、平均と分散を報告すること。

**参照実装**: RAFT (UKPLab/2022-RAFT)、KAT (Adamdad/kat) のコードが公開されている。
safe PAU の実装が正しいかの照合に使ってよい。**ただし丸ごとコピーせず、
自分の実装との差分を理解した上で使うこと。**

### Phase 2: 拡張（Phase 1 完了後・余力次第）

- variance-preserving initialization（KAT の手法）が分母設計とどう相互作用するか。
- スループット・メモリ測定（参考値として）。

> **削除項目: 重心座標（barycentric）表現によるパラメトライズ。**
> 着手条件を「Phase 1 で次数を上げると学習が不安定になる現象が観測された場合」と
> していたが、Phase 1 の第2軸を次数から近似区間に変更したため、
> **この条件は永久に発火しない**。自覚的にスコープ外とする（2026-08-22）。
> ユーザー自身の専門領域に最も近い項目であり惜しいが、
> 「発火しない着手条件を残して、やる気があるように見せる」ことはしない。
> なお近似区間を広げると条件数は悪化する（m=5 で 2.0e2 → 4.4e3）ため、
> R2/R4 で不安定性が出た場合には**条件数の寄与を疑う材料としてのみ**使う。

## 7. 評価指標

| 指標 | 用途 |
|---|---|
| validation perplexity | 主指標（RQ1） |
| 学習曲線（同一ステップ数での loss） | 収束速度（RQ1） |

## 10. 想定される失敗モードと対処

| 失敗モード | 対処 |
|---|---|
| 有理活性化が GELU/SwiGLU を上回らない | **想定内。** RAFT の結果が decoder-only では再現されなかった、という**それ自体が報告価値のある追試結果**になる。無理に良く見せず、なぜ再現しないかを分析する |
| 学習中に `A(x)` の符号変化が一度も起きない | **想定内。** その場合「PAU の非平滑性批判は実務上空振りである」という明確な否定的結論になる。RQ3 はそれで完結する |
| 平滑分母と PAU 型に差が出ない | 符号変化が起きていないなら当然の結果。符号変化が起きているのに差がないなら、それも報告する |
| 学習が発散する | 分母設計・初期化・学習率を切り分ける。R1〜R4 のどの条件で起きるかが RQ3/RQ4 の答えそのものになる |
| **小規模モデルで重い裾がそもそも育たない** | **想定内。** 10〜30M を TinyStories で学習した場合、GPT-2 に見られる outlier features が発生せず、pre-activation が [-3,3] にほぼ収まる可能性がある。その場合は**区間軸も分母軸も差が出ない**。これは「小規模 decoder-only では、近似区間・分母設計のどちらも性能に影響しなかった」という否定的結果として報告する。**無理に差を作らない。** 学習中の分位点記録があるので「裾が育たなかった」ことを実データで示せる |
| 計算資源が足りない | モデル規模とデータを縮小する。**条件の本数を減らすのではなく規模を減らす**（2×2 の比較構造は維持） |
