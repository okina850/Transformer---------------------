## 2. 研究テーマ

**学習可能な有理活性化関数（Rational Activation）の Transformer への適用と、分母設計の改善**

### 一行要約
CNN で提案された学習可能有理活性化関数（Padé Activation Unit 系）を小規模 Transformer 言語モデルの
FFN 層に適用し、既存手法の数値的な弱点（分母の非平滑性）を改善した上で、GELU / SwiGLU と比較評価する。

---

## 3. 背景と先行研究

### 3.1 学習可能有理活性化関数とは
活性化関数を有理関数 F(x) = P(x)/Q(x)（P, Q は多項式）で表現し、その係数を
ネットワークの重みと一緒に誤差逆伝播で学習させる手法。層ごとに最適な非線形性の形状を
自動獲得できる。パラメータ数の増加はごくわずか（PAU では1層あたり10個程度）。

### 3.2 既知の先行研究（`docs/refs/` 配下の PDF を参照）

| 文献 | 内容 | 検証対象 |
|---|---|---|
| Molina et al., ICLR 2020 (`docs/refs/pade_activation.pdf`) | Padé Activation Unit (PAU) を提案。安全化のため分母を `Q(x) = 1 + |Σ b_k x^k|` とし極を回避。次数[5,4]、層ごとに1つのPAUを共有。既知活性化のPadé近似係数で初期化 | CNN 画像分類（MNIST, Fashion-MNIST, CIFAR, ImageNet/MobileNetV2） |
| Boullé et al. (`docs/refs/rational_NN.pdf`) | 低次数 type (3,2) の有理活性化を提案。合成により実効次数が指数的に増える点を理論的に示す。**PAU の絶対値による非平滑性と勾配計算コストを明示的に批判** | PDE 求解、GAN |
| (`docs/refs/rational_activation_function.pdf`) | 一様ノルム（minimax）ベースの損失関数で有理活性化を学習。準凸最適化・二分法・差分修正法を使用。低次数(1,1) | 分類タスク |

### 3.3 文献上のギャップ（本研究の立脚点）

- **Transformer / 言語モデルでの評価が存在しない。** 上記いずれも CNN・PDE・GAN であり、
  自己回帰言語モデルの FFN 層に適用した報告は確認できていない。**これが本研究の主たる新規性である。**
- **「平滑」かつ「極なし」の分母設計が未解決。**
  - PAU: `1 + |A(x)|` → 極はないが A(x)=0 で微分不連続（折れ曲がり）
  - Boullé: 制約なし → 平滑だが極が出うる
  - この中間、すなわち平滑かつ大域的に正の分母、は埋まっていない。**これが本研究の独自改善点である。**

## 4. リサーチクエスチョン

- **RQ1（主）**: 学習可能有理活性化は、Transformer 言語モデルにおいて GELU / SwiGLU と比較して
  perplexity・収束速度の面で競争力があるか。
- **RQ2（主）**: 平滑かつ極なしの分母設計は、PAU 型（絶対値）と比べて学習の安定性・最終性能を改善するか。
  また、その差は次数を上げたときにどう変化するか。
- **RQ3**: 学習後の有理関数の形状は層ごとに異なるか。異なるとしたら、どのような傾向か。
- **RQ4（余力があれば）**: 有理活性化は GELU（erf/tanh 評価を含む）より推論が高速か。

## 5. 独自性の核

### 5.1 主たる新規性: Transformer 言語モデルへの適用
先行研究は全て CNN / PDE / GAN であり、自己回帰言語モデルでの検証は行われていない。
**「適用して評価した」だけでも報告価値がある**が、それに留めず 5.2 の改善を加える。

### 5.2 独自改善: 平滑かつ極なしの分母設計
PAU の `Q(x) = 1 + |A(x)|` を置き換える候補：

- `Q(x) = 1 + A(x)^2` （常に正・C^∞・実装が単純。**第一候補**）
- `Q(x) = 1 + sqrt(ε + A(x)^2)` （絶対値の平滑化。ε はハイパーパラメータ）

いずれも「極を持たないことを構造的に保証しつつ、微分が至るところ連続」という性質を狙う。
Boullé et al. が PAU に対して行った批判に直接応答する形になる。

**注意**: `1 + A(x)^2` は分母の実効次数が2倍になるため、パラメータ数と計算コストの比較時に
次数の定義を揃えること（型の表記を明確にする）。

### 5.3 副次的な検討事項（余力がある場合のみ・必須ではない）

以下は Phase 1 の主要比較が完了した後に、時間が余った場合にのみ着手する。
**これらのために主要比較の完成を遅らせてはならない。**

- **層ごとの学習後形状の可視化・分析**（RQ3）— コストが低いので優先度は比較的高い
- **Horner 法による高速評価とスループット測定**（RQ4）
- **重心座標（barycentric）表現によるパラメトライズ** —
  モノミアル基底 `Σ a_i x^i` は次数が上がると条件数が悪化する（数値解析では周知）。
  有理関数の重心形式は数値的に安定であることが知られている。
  **ただし着手条件を設ける**: Phase 1 で「次数を上げると学習が不安定になる」現象が
  実際に観測された場合に限り、その原因究明・改善策として検討する。
  現象が観測されないなら実装しない。
  （実装上の難所: 学習可能な節点の扱い、x → x_j での除算の分岐処理、勾配の安定性）

## 6. 実験計画

### Phase 0: 事前近似解析（学習不要・最優先・**1週間で完了させる。最初のマイルストーン**）

**目的**: Phase 1 の初期化係数と次数選択の根拠を得る。
学習を一切行わないため、1週間以内に完了できる設計になっている。
着手から1週間時点で、この Phase 0 の成果物一式が「見せられるもの」になっていること。

1. GELU / SiLU(Swish) の Padé 近似を、次数を変えて自前で計算する
   （型: (3,2), (4,3), (5,4), (6,5) など）。近似区間は [-6, 6] 程度を想定。
   - 検証: `docs/refs/pade_activation.pdf` の Appendix Table 6 に [5,4] の係数表があるので突き合わせること。
2. 各次数での最大誤差・L2誤差を測定し、誤差曲線を作る。
3. **学習済みモデル**（GPT-2 small など、Hugging Face から取得）の FFN 活性化を
   上記近似で置き換え、perplexity の劣化を次数ごとに測定する（学習は一切行わない）。
4. 5.2 の各分母設計についても、同様に近似精度と平滑性を比較する。

**成果物**: 次数ごとの近似誤差表、perplexity 劣化曲線、Phase 1 で使う初期化係数。

### Phase 1: 小規模 Transformer の学習と比較（本体・目安1〜2ヶ月）

**モデル**: decoder-only Transformer を自前実装またはミニマル実装（nanoGPT 系）ベース。
規模は 10〜30M パラメータ程度。単一 GPU で 1条件あたり数時間で回ることを必須要件とする。

**データ**: TinyStories または WikiText-103。まず小さい方で回して pipeline を確立すること。

**比較条件（これで確定。勝手に増やさない）**:

| 条件 | 内容 |
|---|---|
| B1 | GELU（ベースライン） |
| B2 | SwiGLU（ベースライン） |
| R1 | PAU 型（`1 + |A(x)|`）、低次数 |
| R2 | PAU 型（`1 + |A(x)|`）、高次数 |
| R3 | 平滑分母（`1 + A(x)^2`）、低次数 |
| R4 | 平滑分母（`1 + A(x)^2`）、高次数 |

低次数・高次数の具体的な型は Phase 0 の結果を見て決める（例: (3,2) と (5,4)）。
R1〜R4 の 2×2 構造により、「分母設計の効果」と「次数の効果」、および
両者の交互作用（高次数で平滑分母の優位が拡大するか）が一度に見える。

**必ず守ること**:
- **パラメータ数を揃えること。** SwiGLU はゲート構造で行列が1枚多いため、
  単純に活性化だけ差し替えるとパラメータ数が不揃いになる。d_ff を調整して揃えるか、
  揃えられない場合はその差を明記すること。
- 同一データ・同一ステップ数・同一ハイパーパラメータ探索予算で比較すること。
- 各条件で seed を最低3つ振り、平均と分散を報告すること（1 seed の結果で結論を出さない）。
- 学習曲線（loss vs step）を必ず記録・保存すること。

**分析**:
- 学習中の勾配ノルム・損失スパイクを比較し、安定性を評価（RQ2）
- 学習後の各層の有理関数を [-6, 6] でプロットし、層ごとの形状差を可視化（RQ3）

### Phase 2: 拡張（Phase 1 完了後・余力次第）

5.3 の副次的検討事項に着手する。
優先順位は 層ごと形状分析 → スループット測定 → (条件付き)重心形式。

## 10. 想定される失敗モードと対処

| 失敗モード | 対処 |
|---|---|
| 有理活性化が GELU/SwiGLU を上回らない | **これは想定内。** 無理に良く見せない。「なぜ上回らないか」（層ごとの形状が結局 GELU に近い、FFN では表現力がボトルネックでない等）を分析することが成果になる |
| 学習が発散する | 分母設計・初期化・学習率を切り分けて原因を特定。R1〜R4 のどの条件で起きるかが RQ2 の答えそのものになる |
| 平滑分母と PAU 型に差が出ない | 高次数の条件（R2 vs R4）に差が出るかを確認する。それでも差がないなら「低次数では分母設計の影響は小さい」という結論で構わない |
| 計算資源が足りない | モデル規模とデータを縮小する。**条件数を減らすのではなく規模を減らすこと**（2×2 の比較構造は維持する） |
