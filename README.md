# GPTの活性化関数を「学習可能な有理関数」に置き換えてみた
## はじめに
一目見てわかる概要として、以下のポスターをご覧ください。(機械学習ワークショップ[「IBIS2026」](https://ibisml.org/ibis2026/posters/)にて発表したものです)
[![Research Poster](./images/poster.png)](./docs/poster.pdf)

以下の章は、文章による概要説明になります。

実験の詳細な設定、過程について知りたい方は、[docs/FULL_REPORT.md](docs/FULL_REPORT.md) をご覧ください。

## 背景

Transformer(GPTなど)のFFN層には、GELUという固定された非線形関数が使われている。
これを、**係数が学習によって変化する、有理関数(多項式÷多項式)に置き換える** 、という
手法(Padé Activation Unit、以下PAU)が2020年に提案されている。

この手法は、BERT系(文章を読んで理解するタイプのencoder onlyのモデル)に適用した先行研究で、
GELUより性能が良くなったと報告されている(RAFT, 2023)。

**この研究は、「同じ手法を、GPT系(文章を生成するタイプのモデル)に使ったら、
同じように性能が上がるのか」を、実際に手を動かして検証したもの。**

## 何をしたか

有理活性化関数を組み込んだ、小さいGPT(1400万パラメータ)を、ゼロから学習させた。
GELU(標準)、SwiGLU(別の代替手法)、有理活性化(4パターン)の、計6条件を、それぞれ
3回ずつ(乱数の初期値を変えて)学習させ、比較した。

## 分かったこと

**1. 性能は、良くならなかった。**

文章の予測精度(perplexity、低いほど良い)を比べたところ、GELUと有理活性化の間に、
意味のある差はなかった。先行研究がBERT系で報告した「性能が上がる」という結果は、
GPT系では再現しなかった。

**2. ただし、副産物として、面白い発見があった。**

有理活性化は、GELUに比べて、**学習中の勾配(パラメータをどれだけ動かすかの指標)が、
2〜2.5倍大きくなる**ことが分かった。これは、分母の設計を変えても変わらない、
「有理関数を使うこと自体」に起因する性質だった。先行研究では、この点は
報告されていなかった。

**3. 事前に立てた予測が、的中した。**

有理活性化関数は、GELUに近い形になるよう、限られた範囲(-3〜3)で調整して
初期化されている。しかし、実際にモデルを学習させると、この関数に入ってくる値は、
学習が進むにつれて、その範囲を超えて広がっていくことが、測定で確認できた。
「範囲の外側で、想定と違う挙動をするのでは」という懸念は、正しかった。

**4. 先行研究と全く同じ設定を再現したところ、学習が不安定になるケースがあった。**

3回の試行のうち1回、途中で学習が破綻(発散)した。頻度は低いが、
「同じ設定を再現しても、GPT系では、安定して動くとは限らない」という事実が観測された。

## この研究で、特に意識したこと

- **結果を見る前に、「何をもって良い/悪いと判定するか」を先に決めて、後から変えなかった。**
  これにより、自分に都合の良い基準を、後付けで選んでしまうことを防いだ。
- **自分自身の測定ミスを、後から見つけて訂正した記録を、隠さず残している。**
  一度、比較の条件が揃っていない状態で結論を出しかけたが、これに気づき、
  測定し直して結論を修正した。
- **「なぜ、この設計にしたか」を、常に、数値的な根拠と一緒に残した。**
  例えば、活性化関数の分母の形を1つに決める際、「精度」と「安定性」という
  2つの効果が同時に変わってしまわないよう、注意深く設計を分離した。
